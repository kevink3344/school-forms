1. Getting started

1.1 What an administrator can do

An administrator account can do everything a staff member can, plus the work that shapes what everyone else sees. In practice that means:

  • Design and publish forms — the questions parents answer, and the staff-only fields your staff fill in.
  • Decide who can see what — public or private forms, which roles see which staff-only field, and which menu items each role gets.
  • Manage accounts and roles — create users, reset passwords, and define what a role may do.
  • Watch the plumbing — the Webhook Log shows every response Google Forms sent, including the ones the app rejected.
This guide and the Settings Reference

Day-to-day work — forms, submissions, reports, access — is in this guide. The twelve Settings sections are in the companion Settings Reference, one chapter per section. Both are printable and use the same conventions.

1.2 Signing in

Open the School Forms address and sign in with the email address and password for your administrator account.

If the screen looks different

An administrator controls the sign-in mode in Settings → Login Mode. If you see Organization and Test User lists instead of the two boxes, the installation is in test mode; if you see an amber maintenance message, sign-in is switched off. See the Settings Reference, chapter 3.

1.3 Finding your way around

You land on Submissions. The menu is closed so your work has the full width of the screen — click the menu button in the top-left corner.

Menu items can be hidden

Forms, Available Forms, Access Requests and Reports are each switchable per role in Settings → Menu Settings. If a colleague cannot see one, that is a setting, not a fault. Settings itself is always available to administrators.

2. Submissions

2.1 The dashboard

The Dashboard lists every submission across every school in your organization.

2.2 Filtering and searching

Narrow the grid with the four filters in the bar. Clear resets every filter, including the form.

  • Search matches any answer on the row. Use Search in to restrict it to one column — for example, a course name in Course choice #1 only.
  • Picking a Form is what makes that form's fields available as columns and as search targets.
  • Staff-only columns sort to the right-hand end and are tinted. You can edit them in place, exactly as staff do.
Archived submissions are hidden by default

An archived submission disappears from this grid, from exports, from reports and from the documents list. It is not deleted — see 2.4 for restoring it.

2.3 Exporting

The file downloads as submissions-export.csv. For Excel or PDF, or to save the setup for next time, use Reports instead.

2.4 Reviewing and archiving a submission

Click a student's name or Review to open the submission. The page is the same one staff use, with two additions only an administrator sees:

  • Delete permanently — appears on an archived submission only, and cannot be undone. The dialog names the student and states that the generated Google Doc itself is not deleted, only the app's link to it.
  • Promote to form field — on the Additional fields card, when a Google Form asked a question that was never defined in the designer. Promoting it adds a real field to the form and migrates every matching answer.

Everything else — Select Status, Edit for a parent's answers, Save staff fields, Archive and Restore — works exactly as described in the Staff Guide, Part 5.

3. Forms

3.1 The Forms list

Delete is disabled once a form has submissions

That is deliberate: submission data is never lost to a mis-click. To retire a form that has been used, Archive it instead — it stops accepting submissions and every submission is kept.

3.3 Form Details

There is no "generate fields from Google Form"

The Google Form URL is a link for staff to follow. Fields are always built by hand in the designer. A question a Google Form asks that the designer does not define is still captured on the submission and can be promoted later — see 2.4.

3.5 Staff-only fields and access

Why the Access row matters

This is how you keep a field visible to Administrators only, or to Administrators and School Contacts but not Staff. A role created later starts with no access to existing staff-only fields until you grant it here.

3.6 Visibility: public and private

3.7 Publishing and the public link

Unpublishing keeps existing submissions

Unpublish stops the form accepting new responses; everything already submitted is untouched. Responses that arrive while a form is unpublished are rejected and recorded in the Webhook Log — publishing the form again makes them deliverable.

4. Access requests

When a form is private, an account that cannot read it can ask for access. Those requests arrive here, and in the bell in the banner.

Approving is the same as ticking the box

An approval creates the same grant you would create by ticking the form in Settings → Users → Edit User. Either route works; this one is just faster when several people are waiting. A declined request stays re-requestable — the person can ask again.

5. Reports and export

5.1 Building a report

  1. Pick a Form.
  2. Narrow the rows with School, Status and Search.
  3. Choose columns and, optionally, a Group by.
  4. Pick a Format and click Export.
What you see is what you get

The preview and the exported file come from the same query, so the file always matches the screen. Saved views are private to the account that made them.

6. Webhook Log

The Webhook Log is the answer to "a form looks empty — did anything actually arrive?" It lists every response Google Forms posted to the app, including the ones it rejected.

ReasonMeaningReplayable?
SucceededAccepted; a submission was created.—
form_not_publishedThe form was not published when the response arrived.Yes, once published
invalid_bodyThe payload was missing required keys.No
form_not_foundThe form id does not exist.No
unauthorizedWrong or missing secret. Logged without the payload.No
internal_errorThe server failed.Yes
The common case

If responses stopped arriving because a form was unpublished, publish the form and click Replay on the affected rows — or Replay all failed once a form is selected. The stored responses are re-sent and the submissions appear.

8. Your account

Changing your password does not sign out other sessions

Copies of School Forms already open elsewhere stay signed in. If you think someone else is using your account, change the password and review Settings → Users.
